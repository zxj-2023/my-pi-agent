# 上下文四层廉价优先压缩管线设计规范 (`my_agent_core.context`)

- **定位**：长文本上下文动态管理与 Token 预算压缩引擎 (`packages/my-agent-core/src/my_agent_core/context.py`)
- **核心类**：`ContextManager`, `ContextSessionBridge`
- **压缩流水线**：L3 ➔ L1 ➔ L2 ➔ L4

---

## 一、架构设计与定位

随着对话轮次增加，上下文极易超出模型的最大 Token 限制或导致推理成本暴涨。
`ContextManager` 实现了 **廉价优先（Cheap-first Pipeline）** 的四层递进式压缩策略，力求在不花额外 LLM 调用的前提下优先压缩，仅在必要时才调用大模型进行结构化摘要。

```text
                           原始消息列表 (self.messages)
                                        │
                                        ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                       ContextManager.prepare(messages)                      │
├─────────────────────────────────────────────────────────────────────────────┤
│  第 1 步: 【L3 大结果落盘】                                                  │
│    超大工具输出写入 .my_agent_core/results/ 文件，上下文中替换为路径占位符     │
│    (0 API 损耗)                                                             │
│  ─────────────────────────────────────────────────────────────────────────  │
│  第 2 步: 【L1 中间轮次裁切】                                                │
│    固定保留 System 提示词与最近 N 轮对话，将中间过早的轮次裁切剔除           │
│    (0 API 损耗)                                                             │
│  ─────────────────────────────────────────────────────────────────────────  │
│  第 3 步: 【L2 旧结果占位替代】                                              │
│    过早历史轮次中的工具返回结果替换为短占位符 "[output omitted]"            │
│    (0 API 损耗)                                                             │
│  ─────────────────────────────────────────────────────────────────────────  │
│  第 4 步: 【L4 LLM 智能结构化摘要】                                          │
│    若上述 3 层仍超预算，花费 1 次 API 将被截断的历史总结为结构化摘要          │
│    (只有超阈时才花 1 次 API)                                                │
└───────────────────────────────────────┬─────────────────────────────────────┘
                                        │
                                        ▼
                   返回发给大模型的非破坏性压缩视图 (view)
                     (self.messages 真实历史保持 100% 完整)
```

---

## 二、关键机制与技术实现

### 1. Usage 动态锚定（Token Usage Anchoring）

- **混合估算模型**：日常以 `len(text) // 4` 进行轻量预估；
- **动态校准**：每轮大模型返回时，调用 `_ctx.record_usage(last_usage)` 用官方 API 返回的真实 token 消耗反向校准基线，精度远高于纯字符盲估。

### 2. `retainedTail` 持久化快照缓存

每次执行 L4 摘要后，`ContextManager` 会把“摘要正文 + 裁切点之后的尾部消息哈希”固化为一个特殊的 `compaction` 条目存入 Session 树。

- **重启免重算**：会话重新打开时，`ContextSessionBridge.restore_cache()` 可以秒级还原压缩态，无需重新花 Token 调用模型总结历史。

### 3. `compaction_floor` 指针护栏

- 当发生过压缩后，`compaction_floor` 记录当前有效的压缩基线节点；
- 执行 `rewind` 时，指针只能回退到 `compaction_floor` 之后，彻底防止指针回退到已摘要的历史节点导致缓存被破坏。

### 4. 摘要提示词防注入与标签剥离

调用大模型生成 L4 摘要时：

- 系统强制采用 `<analysis>`（让模型先分析上下文重点）和 `<summary>`（正式输出摘要）双标签结构；
- 最终提取时严格剥离 `<summary>` 内的正文，防止历史对话中恶意的 Prompt 注入伪造摘要。
